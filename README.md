# iidp

`iidp` is the CLI for Itema's Internal Developer Platform. A developer runs `iidp app create`, answers a handful of questions (or passes every answer as a flag), and gets a complete Application: a repository, a Dockerfile, a CI pipeline, an address with TLS, and the Capabilities it asked for, such as a Postgres database, a `staging` Environment, a custom domain or Itema login. The CLI never talks to Kubernetes. It writes the desired state of each Application to the Platform repository, and the Platform reconciles from there. Both Create (a new Application repository generated by the CLI) and Adopt (an existing Application repository, changed through a pull request) are supported.

The vocabulary used throughout this repository is defined in [`CONTEXT.md`](CONTEXT.md).

## Install

On macOS, with Homebrew:

```sh
brew install --cask Itema-as/tap/iidp
```

On Linux, or without Homebrew, download the archive for your platform (macOS or Linux, amd64 or arm64) from the [GitHub Releases](../../releases) page, unpack it and put `iidp` on your `PATH`.

Check the installation with:

```sh
iidp version
```

## Repository layout

The layout follows [`docs/design.md`](docs/design.md):

```
cmd/iidp/            CLI entrypoint
internal/            wizard, github, platformrepo, render
chart/application/   the generic Helm chart
infra/               OpenTofu for the node, cloud-init for k3s
bootstrap/           ArgoCD app-of-apps for Platform components
scripts/bootstrap-wizard.sh
docs/adr/
docs/design.md
CONTEXT.md
```

The GitHub org and the Platform repository name are compiled into the binary in `internal/platform`. Everything else the CLI needs to know about the Platform is read from `platform.yaml` in the Platform repository.

## Developing

Go, as pinned in `go.mod`. Before pushing:

```sh
gofmt -l .        # must print nothing
go vet ./...
go test ./...
```

CI runs the same on every pull request and on pushes to `main`, and validates `.goreleaser.yaml`.

## Releasing

A release is one tag:

```sh
git tag v0.1.0
git push origin v0.1.0
```

The `Release` workflow runs GoReleaser, which builds darwin and linux binaries for amd64 and arm64, publishes them with checksums to GitHub Releases, and updates the Homebrew cask in `Itema-as/homebrew-tap`. Pre-release tags such as `v0.2.0-rc1` are published as GitHub pre-releases and do not touch the tap.

Updating the tap needs a token the default workflow token does not have. Create a fine-grained personal access token (or a GitHub App token) with **Contents: read and write** on `Itema-as/homebrew-tap` only, and store it as the repository (or org) Actions secret `HOMEBREW_TAP_GITHUB_TOKEN`. The `version` a released binary reports comes from the tag, injected at build time; a plain `go build` reports `dev`.

To try the release build locally without publishing anything:

```sh
goreleaser check
goreleaser build --snapshot --clean --single-target
```
